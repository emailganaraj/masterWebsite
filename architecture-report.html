Production Article Publishing Platform — Architecture Report

Project: D:\masterWebsite
Domain example: myArticleWebsite.com
Date: September 20, 2026
Hosting choice: Self-hosted VPS/Docker + PostgreSQL + Cloudflare CDN
Content model: Mixed evergreen + timely (stable URLs, dates on page only)

Executive Summary: Build a modular monolith using Next.js 15+ (App Router), PostgreSQL 16, Drizzle ORM, TipTap editor, Cloudflare R2 for media, and pg-boss for background jobs. Public pages use ISR + CDN caching so content is database-driven but NOT database-hit on every request. SEO-first server-rendered HTML. No Redis, Elasticsearch, or separate API server on day one — add when metrics justify it.

1. Research Findings

1.1 Documented Facts

SourceKey Pattern
Ghost CMSDecoupled JSON REST API. Content stored as Lexical JSON. Default post URL is /{slug}. Tags at /tag/{slug}/. Headless mode requires rebuilding sitemap/SEO yourself.
WordPress VIPGlobal edge page cache (default 30 min). Stale-while-revalidate up to 12h. Publish auto-purges related URLs. Media on object store.
Next.js ISRPre-render + on-demand generation. revalidateTag on CMS publish. Sitemap indexes split at ~50k URLs.
The GuardianURLs: /section/yyyy/mon/dd/story-slug — date + section + slug for news.
MediumSlug frozen at publish. Immutable 12-char hex ID appended.
NYTArticle URL stable 6 days, then migrates to archive URL.
Google DiscoverNo special tags required. max-image-preview:large. Hero images ≥1200px. AMP NOT required.
AdSense API v2OAuth 2.0. Scope: adsense.readonly. Reports via accounts/{id}/reports:generate.
Reddit Hotsign(score) * log10(max(abs(score),1)) + (epoch - 1134028003) / 45000
Hacker News(points - 1) / (age_hours + 2)^1.8 — time decay dominates.

1.2 Reasonable Inferences

INFERENCE NYT, BBC, Vox, BuzzFeed, Forbes, TechCrunch use CDN-first HTML, async analytics, redirect tables — exact stacks not public.

INFERENCE Large SEO publishers decouple canonical URL from taxonomy.

INFERENCE Recommendations at scale use offline scoring + cached results; vector search added later.

1.3 Common Patterns

  • Database = source of truth; HTML generated server-side and CDN-cached
  • Publish triggers targeted cache invalidation
  • Media on object storage + CDN
  • Async analytics pipeline
  • Structured JSON content rendered to semantic HTML
  • 301 redirect table for slug changes
  • Separate strategies for Latest, Popular, Trending, Related

3. Database-Driven Content — Rendering Strategy

Principle: Database-controlled ≠ database-hit on every request.

CORRECT:  PostgreSQL → Server Component → ISR Cache → Cloudflare CDN → User/Googlebot
WRONG:    Browser → Client JS → API → DB → Render (bad SEO)
PageStrategyRevalidation
/article/[slug]ISRrevalidateTag('article:{slug}')
/category/[slug]ISRrevalidateTag('category:{slug}')
/ (homepage)ISR 60-300srevalidateTag('homepage')
/searchSSRnoindex, short/no cache
/admin/*SSR, no cacheN/A

Article body: TipTap JSON → generateHTML() server-side via @tiptap/html.

4. URL Architecture

Decision: Stable /article/{slug} — NO category or date in path.

RoutePatternExample
Article/article/{slug}/article/how-the-world-is-viewing-you
Category/category/{slug}/category/comedy
Tag/tag/{slug}/tag/celebrity
Author/author/{slug}/author/jane-doe
Search/search?q=noindex on results
Lists/trending, /latest, /popular—
  • Lowercase, hyphen-separated, unique slug (DB index)
  • Category/tag/author changes do NOT change canonical URL
  • Slug change → 301 via redirects table
  • Dates in page content + JSON-LD, NOT in URL

10. Homepage

Configurable via homepage_sections. Sections: Hero (1), Trending (6-8), Latest (8-12), Popular (6-8), Editor's Picks, Category blocks (3-4 each), Recommended. Each = one efficient LIMIT query. Ad slots between sections. ISR 60-300s.

11. Article Page

Server-rendered HTML with: breadcrumb, category, H1 title, subtitle, author, dates, featured image (≥1200px), body, internal links, related/recommended/popular, ad slots. Google never needs JS for article text.

15. SEO

Every page: title, meta description, canonical, OG tags, Twitter Card, max-image-preview:large, single H1, JSON-LD (Article, BreadcrumbList, Person, Organization, WebSite), time elements.

Sitemap: dynamic, index at 50k URLs. Robots: block /admin, /api. Thin tags (<3 articles) → noindex.

22. Trending System

score = (views_2h * 3 + views_24h) / POWER(hours_since_publish + 2, 1.5)
Recomputed every 5 min. Configurable weights in site_settings.

29. Caching

Browser → Cloudflare CDN → Next.js ISR (tag invalidation) → PostgreSQL
Cache: articles, categories, homepage, trending, media
Don't cache: search, admin, /recommended (personalized)
Publish → revalidateTag(article, category, homepage, sitemap, trending)

30. URL Redirects

Slug change → INSERT redirects (301). Middleware checks before 404. Prevent chains (A→C not A→B→C).

31. Content Versioning

article_revisions: full JSONB snapshot per save. Version, editor, timestamp, summary. One-click restore creates new revision.

32. Scheduled Publishing

Status: draft → review → scheduled → published → archived. pg-boss cron every 60s checks scheduled_at ≤ NOW().

33. Monetization

v1: AdSense via AdSlot. Future: direct ads, affiliate, sponsored, newsletter, premium. ad_slots.type enum ready.

34. Performance

Targets: LCP <2.5s, INP <200ms, CLS <0.1. ISR, CDN, WebP/AVIF, lazy ads, font subsetting, pagination, DB indexes.

35. Mobile-First
